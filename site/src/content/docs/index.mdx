<Section kicker="Protocols" title="Six protocols, one shape of data">
  Every connector publishes the same `sample`, `status` and `cmd` envelopes on
  `te/device/<device>/ot/<protocol>/…`, so a flow, a dashboard or a cloud integration written
  once works for all of them.
  <ProtocolGrid slot="body" />
</Section>

<Section kicker="Packages" title="Two packages, one contract">
  The same `tedge-dot` exists twice, written in Rust and in C, released together and held to the
  same test suites. Start with `tedge-dot-c`; configs and flows work unchanged on both. Whether
  both remain in the final product is not decided yet.
  <TwoPackages slot="body" />
</Section>

<Section kicker="Quick start" title="Read a PLC in a minute">

  with the CLI.

</Section>
