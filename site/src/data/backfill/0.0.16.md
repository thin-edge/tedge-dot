### OPC UA method calls

A point can now be an OPC UA **method**: `access = "call_method"` with
`address = { object_id, method_id, inputs = [...] }`. The new `call-method` command takes
`arguments` and returns the method's `outputs`. Both packages support it, with identical failure
reasons.

```toml
[[device.point]]
id      = "multiply"
access  = "call_method"
address = { object_id = "ns=2;s=Machine", method_id = "ns=2;s=Machine.Multiply", inputs = ["int32", "int32"] }
```

- `ot-registration` announces a device's methods as the retained `ot_call_method` command
  capability, and `ot-command-forward` routes an `ot_call_method` command to the connector. The
  outputs come back on the command.
- A method call is never retried. A call that times out may still have run on the server.
- Method ids follow the device's namespace table (below).
- **Breaking, `tedge-dot-rs` only:** a write-only point (`access = "write"`) is no longer polled and so no longer
  publishes samples, as the contract always required (`tedge-dot-c` already behaved this way).
  Declare it `read_write` to keep its samples.
- See `doc/connectors/opcua-connector-spec.md` §3.10 and contract §6.6.

### OPC UA namespace tables

An OPC UA node id such as `ns=3;i=1234` names its namespace by position in the server's
namespace array. A firmware update, or another instance of the same device type, can number the
namespaces differently, and the id then reads a different node, or none. A device
(`protocol_address.namespaces`) or a point library (`[library] namespaces`) can now record the
array its ids were written against. On every connect the connector maps each index through
that table to the server's current one, and logs a namespace that moved.

- Node ids stay numeric, as copied from UaExpert. Without a table nothing changes.
- A namespace the server does not list fails only its own points (`namespace not found: <uri>`)
  and is tried again, so one the server adds later is picked up.
- Both packages support it. An older package ignores a device's table and reads the configured
  index. It rejects a library that carries one.
- See `doc/connectors/opcua-connector-spec.md` §3.9.
